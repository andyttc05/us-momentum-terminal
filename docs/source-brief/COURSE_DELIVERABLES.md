# IEDA 1180 Course Deliverables and Academic Constraints

This file summarises the uploaded `IEDA_1180_Course_Project_Guidelines_Fall_2026.pdf`. The original PDF is retained in `SOURCE_DOCUMENTS/` and is the authority for course requirements.

## 1. Course project principles

- Choose an interesting question and write it in one sentence.
- Explain why the question is interesting/useful and what makes it new or different.
- Use existing real data; the course brief says not to create your own data or collect data yourself.
- Use Python and skills learned in class to answer the question.
- Explain data sources and the meaning of important fields/columns.

## 2. Team arrangement and grading

- The course permits working alone or in a group of two. A group submits one proposal and one final project.
- If working in a group of two, the proposal and final project must state each member's contribution.
- The brief states that the project grade has two parts: 80% for the student's own reviews and 20% for project quality.

## 3. Submission requirements from the course brief

### Proposal

- Due: November 11, 2026.
- PDF of one or two pages.
- In the student's own words.
- Include the question, data/source, Python plan/calculations/comparisons, and intended output.
- The brief says AI may be used for help, but students must not copy/paste AI-written sentences or paragraphs into the proposal.

### Final project

- Due: November 26, 2026.
- A4 PDF report, no more than five pages.
- In the student's own words.
- Include:
  - Question and data source, plus important columns/values.
  - Explanation of code, data changes/cleaning, missing data treatment and class skills used.
  - Results with clear tables/figures and explanation.
  - What the data cannot tell you / limitations.
- Submit Python notebook or scripts, data files or source links, and instructions that allow another person to reproduce the results.
- Use NumPy and pandas when useful.

## 4. Review requirements

The course grading guidelines specify 10 proposal reviews per student by November 17, 2026 and 10 final-project reviews per student by December 6, 2026. Each review must:

1. Answer every question in the review round.
2. Refer to details in the reviewed project.
3. Explain reasons.
4. Suggest at least one clear change and explain how it helps.

The brief strongly discourages AI-written review comments and says reviews must be the student's own work. Do not use an agent to write or submit student reviews.

## 5. AI-use disclosure and student responsibility

The brief allows AI tools to help with the project, but requires students to:

- Say which AI tools were used and what they helped with.
- Check code, calculations, answers and results before submission.
- Ensure results agree with data and calculations.
- Understand the work and be able to explain it.
- Write the proposal and final report in their own words; do not copy/paste AI-generated sentences or paragraphs.

Agents may help with code, testing, debugging, structuring and explanations. The student must verify the implementation and author the submitted report in their own words in accordance with the brief.

## 6. Scope implication for this application

The full product blueprint is broader than what may be necessary to demonstrate the course project. Protect the course deliverables by building the reliable MVP first: real data, explainable Python calculations, reproducible results, concise tables/figures and run instructions. The UI can support the project, but it does not replace the required report, code and data/source reproducibility.
